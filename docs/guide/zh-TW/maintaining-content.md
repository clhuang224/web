# 內容維護練習

前面已經看過內容與版型如何分開，接著可以用一段作品摘要確認這個分工。先修改既有資料，觀察列表與詳情頁的變化，再考慮新增項目。

操作前先確認工作目錄的差異，保留其他尚未完成的修改。

以下是維護步驟與預期結果，不是每個環境都已重跑過的自動化教學。檢查命令以主站現有 scripts 為準。

## 練習一：改一段作品摘要

1. 打開 `src/content/projects.ts`，找到既有作品。
2. 修改它的 `summary['zh-TW']`，再對照英文與日文，確認三段仍在描述同一個作品。
3. 保留 ID、正式網址和原始碼網址。這次只觀察內容變化。
4. 用主站開發或預覽流程打開作品列表、首頁與詳情頁，確認使用到這段摘要的地方有更新。
5. 在詳情頁切換語言，確認仍是同一個作品，目的地連結也一致。

你應該能看到：資料改變，原本的頁面和卡片繼續使用同一個版型。若想改的是版型，才需要往元件走。

## 練習二：理解新增作品會碰到什麼

目前 `projects` 同時供首頁精選與作品列表使用。增加一筆資料可能同時影響兩個畫面；不能先假設它已分成「全部作品」和「首頁精選」兩份清單。

若需要只在列表新增作品，應先明確增加精選關係，再處理新項目。資料至少需要唯一 ID、名稱、三語摘要、標籤、正式網址與原始碼網址；內容必須來自可確認資訊。

有效路由 ID 由 `catalog.ts` 從清單推導。新增資料後，還要確認詳情頁、路徑解析、返回列表和語言切換，而不只是列表多了一張卡。

現有內容測試對首批三件作品有明確預期。產品清單有意改變時，也要同步調整那個預期，保留它真正想驗證的條件。

## 練習三：替換首頁精選文章

打開 `src/content/articles.ts`，檢查一筆文章的 ID、日期、三語標題與摘要、原文網址。替換時先確認原文存在，再讓各語言摘要忠於同一篇文章。

預期結果是首頁顯示新的選文，卡片仍打開原本網誌上的中文文章。其他語言的卡片應維持中文目的地提示。

目前精選資料是手動維護，不會因為網誌發新文章就自動更新。[內容與三語](content-and-i18n.md)說明了這個責任邊界。

## 練習四：理解新增一張塗鴉的影響

先看 `docs/assets.md` 和 `src/content/doodles.ts`。新素材需要保留原檔、記錄來源與檔名對照、使用穩定且不重複的 ID，並提供能從圖片確認的三語描述。

若作者提供日期與原文，編輯 `src/content/doodles/<ID>.md`，例如 `01.md`。檔案開頭的 frontmatter 是由兩條 `---` 包住的資料欄位；目前只使用可選的 `date`，需用引號包住日期字串。其餘內容直接寫 Markdown，各語言頁面共用這份中文，不需要新增標題欄位。

可使用段落、換行、粗體、斜體、行內程式碼、連結、標題、清單、引用、程式區塊和分隔線。連結使用完整的 HTTPS 或 mailto 網址；目前不處理文章內圖片與表格。圖片由塗鴉本身提供，原始 HTML 以文字呈現。

About 的原文同樣直接編輯 `src/content/about.md`。

`pnpm run generate:content` 將這些檔案解析為型別化區塊，再由 Lynx 元件渲染；`dev` 會監看 Markdown，`build` 會先產生內容。不要直接修改產生的 `src/content/doodle-stories.ts` 或 `src/content/about.ts`。

有時間資訊的圖片檔名使用 `YYYYMMddHHmmss.png`，缺少的部分補零；例如只知道到分鐘，最後兩位秒數就是 `00`。清單會依產生的時間字串取得圖片，所以補日期時也要將對應的原檔改名並更新素材目錄，再執行 `pnpm run generate:placeholders` 產生對應縮圖。完全沒有日期時保留舊檔名，`/drawing/01` 這類穩定 ID 也維持不變。

目前清單與測試明確以 `14` 張、兩位數 ID 和既有圖片尺寸為基準。增加第 `15` 張不是單純把檔案丟進資料夾：要一起調整內容預期，並驗證桌面最後一組只有一張時的呈現。

`stepIndex` 的組數計算可以處理尾組，但這不代表卡片寬度、輪播留白與每張圖片可見性都已經驗證過。新增內容也能暴露原本沒遇過的版面情境。

## 改完怎麼確認？

| 變更       | 先確認                                       |
| ---------- | -------------------------------------------- |
| 文案與翻譯 | 型別、內容測試、三語實際閱讀。               |
| 目的地網址 | 網址格式、實際開啟結果、Web 與原生外連方式。 |
| 清單與 ID  | 重複 ID、詳情路由、返回與語言切換。          |
| 圖檔       | 檔案完整性、素材記錄、Web 與原生載入。       |

相關來源連結集中在[原始碼地圖](source-map.md)。檢查的目的，是確認改動造成的實際行為，而不是為了湊一串全部通過的命令。
