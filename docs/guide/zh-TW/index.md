# 這個網站怎麼做的

你正在看 Lynn’s 的幕後。這裡把網站本身當成例子：按下一張塗鴉、切換語言、打開作品，接著沿著同一個動作，看看程式怎麼把結果送到畫面上。

網站的頁面介紹作品，這份文件介紹網站如何成為一件作品。你可以只看取捨，也可以一路讀到 VueLynx、平台轉接和原生端的差異。

- **只是好奇網站怎麼做：** 先讀[選擇與取捨](design-decisions.md)，再看[原生端探索](native-exploration.md)。

## 這裡的教學以什麼為準？

這份指南以專案實作為案例，主要閱讀基準為 `4350530`。原始碼連結指向 [GitHub](https://github.com/clhuang224/web)，後續版本可能已改變；找不到對應行為時，可以用[原始碼地圖](source-map.md)核對檔案與版本。

VueLynx 採用 Vue 的自訂 renderer。熟悉 Vue 的資料流會很有幫助，但 DOM、瀏覽器 API 和 Vue DOM 元件庫的相容性需要分別判斷。[官方介紹](https://vue.lynxjs.org/guide/introduction)提供了基礎對照。

文件會區分三種狀態：**程式已有實作、專案已有驗證紀錄、仍待驗證的延伸**。例如目前已有 Lynx Explorer 的 Android 執行路徑，卻不代表已有可獨立發佈的 App，也不代表每個可及性情境都已通過。

## 可以從這裡帶走什麼？

最有用的收穫，是練習把畫面、規則、資料與平台能力分開思考。這些邊界不只適用於個人網站，也能用來理解換 renderer、接原生功能、整理內容系統，以及判斷測試究竟保證了什麼。

如果想直接動手，從[新增一段作品翻譯的練習](maintaining-content.md)開始。若想先理解整體，前往[閱讀地圖](reading-map.md)。
