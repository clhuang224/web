# 選擇與取捨

這個專案有兩個目標：延續原本的個人網站設計，以及透過實際功能認識 Lynx。選擇 VueLynx，讓網站的實作過程也能成為技術探索的一部分。

Lynx 與 Lynn’s 在名稱上的呼應，也讓這個選擇多了一點趣味。

## 熟悉的 Vue，不同的 renderer

Vue 是熟悉的起點。保留 SFC 和 Composition API，讀元件時還是看得懂資料怎麼流；接著才把注意力放到 Lynx 的元素、事件、樣式和平台能力。

熟悉 Vue 仍然需要確認 renderer 的相容範圍。原本的元件庫可能依賴 DOM，更新網址需要瀏覽器，圖示到了原生端也有不同的載入方式。這些都是這個專案實際要處理的部分。

所以這次選型想探索的是：用同一種寫元件的方式，走進不同的執行環境，會在哪裡遇到差異？

[從 Vue 到 Lynx](vue-to-lynx.md)會先拆開語法與渲染目標的差別。

## 個人首頁、網誌與作品站各自有責任

首頁介紹精選作品、文章與塗鴉。作品和塗鴉有站內列表及詳情頁，文章則打開原本的中文網誌。

既有的文章和作品已經各自有地方可以看，先保留它們的網址，首頁就能專心整理入口。這樣第一版也可以維持純前端。

不過點連結之後會離開目前的內容，所以還是要讓人知道會去哪裡、文章是什麼語言，以及要怎麼回來。

首頁採精選資料，不宣稱自動提供最新文章。內容來源和更新責任可以在[三語內容](content-and-i18n.md)中看到。

## 原始設計保留個性，版面承接新情境

白色側欄、淡水藍底、珊瑚粉、描邊標題與原始塗鴉，來自 [Figma 設計](https://www.figma.com/design/OzWLzG1nfBsVsRTJw029Y4?node-id=2-4)。這些共同構成辨識度。

桌面輪播一次兩張，手機改為一張；手動控制、暫停與減少動態效果的處理補上了使用情境。調整的判準是能否讀清楚、操作得到，而不只是把桌面畫面等比例縮小。

素材與呈現分開維護。原始圖片保持完整，縮放和框線交給版型處理；詳見[樣式與素材](styling-and-assets.md)。

## 網址與畫面分開擁有

Web 端讓瀏覽器 host 管理公開網址、History 和語言偏好，Lynx 內部 Router 管理要渲染哪個頁面。原生 standalone 路徑則直接維護頁面狀態。

這個安排多了一層同步，不過也讓元件可以只說自己要去某個作品頁。至於要不要改網址、怎麼處理上一頁，再由平台決定。接著可以從[一次作品導航](routing.md)看這個分工。

## 文件也是網站的一個入口

網站剛好就是現成的教材，所以把教學也放在網站裡。看完一個功能，可以沿著同一個操作去讀它的程式，順便理解當時的需求和現在的分工。

文件由 VitePress 建置，和主站共用發佈流程。About 介紹個人，網誌放完整文章，幕後則慢慢把這個網站的實作講清楚。

## 值得繼續探索的方向

- 在 Android 比較圖檔、外部連結、返回和生命週期，找出真正的平台差異。
- 用相同的純函式做可互動的規則解說，檢查規則是否真的獨立於 renderer。
- 用可重現的檢查紀錄補上跨平台案例，讓結果能被後來的讀者驗證。

這些延伸的進度與限制整理在[原生探索](native-exploration.md)和[測試與可及性](testing-and-accessibility.md)。
