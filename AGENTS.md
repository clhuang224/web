# Project Guide

Lynn's is a frontend-only personal website built with VueLynx and a browser host. The first application foundation exists; editorial content, accessibility verification, and production deployment remain in progress.

## Documentation Ownership

- `README.md`: product overview, current status, verified setup commands, and documentation links.
- `docs/plan.md`: product direction, scope, decisions and reasons, design direction, open questions, and next steps.
- `docs/architecture.md`: implemented structure and current boundaries. Keep proposed architecture in the plan until it exists.
- `docs/assets.md`: asset provenance, filename mapping, and ordering rules.
- `CLAUDE.md`: imports this guide so contributor instructions have one owner.

Write developer documentation, identifiers, comments, and commit messages in English. Public-facing interface and content resources support `zh-TW`, `en`, and `ja`.

Record decisions in project terms, with their rationale and scope. Do not include private conversations, transcripts, quotations from discussions, role reports, or the sequence of a planning session. Distinguish implemented behavior from planned work.

## Product Boundaries

- Keep the first release frontend-only. The blog and existing project sites remain independent destinations.
- Maintain an original About page and an internal portfolio listing. The maintainer supplies the About copy; do not invent personal details or independently draft a biography.
- Use selected articles rather than promising automatic latest-post updates.
- Localize interface text and content metadata into all three supported languages; article bodies remain Chinese. Use Traditional Chinese initially and respect explicitly localized URLs.
- The homepage carousel displays and advances two doodles on desktop and one doodle on mobile. Support automatic playback and manual controls, including pause and resume, in both layouts.

## Implementation Conventions

The implementation uses VueLynx 0.5.1, Vue 3.5, Rspeedy 0.13.5, and Rsbuild 1.7.3. Web Core 0.26.8 and the CSS extraction plugin 0.7.0 are overridden in `pnpm-workspace.yaml` to keep the selected release line compatible. Do not independently upgrade these packages without repeating build and browser checks.

This project values exploration of Lynx's renderer, event system, and platform model. Components use Lynx elements and events; Vue DOM libraries and Vite integrations are not interchangeable with the selected toolchain. UnoCSS is generated by its CLI at build time, while semantic styles and CSS variables live in `src/styles/site.css`.

- Enable TypeScript strict mode. Use proper types or narrow `unknown`; do not use `any`.
- Use English string literal values for domain states and separate them from translated display labels.
- Keep translatable interface copy in `src/content/copy.ts` and editorial resources in `src/content/`.
- Keep localized editorial content separate from layout and keep external destinations consistent across translations.
- Keep browser globals in `src/host/`. Components and app/platform modules use the typed `SiteHost` bridge for navigation, locale changes, and external destinations.
- Keep public URL/history ownership in the browser host; the application's Vue Router uses memory history. Preserve page identity when switching languages.
- Prefer Vitest for JavaScript and TypeScript tests.
- Use Remix Icon for interface icons and preserve the original brand artwork.
- Keep changes scoped; do not reformat or refactor unrelated files.

## Asset Maintenance

Preserve the supplied images without redrawing, recompressing, or cropping the source files. Apply presentation changes separately from the source artwork. Maintain the asset catalog when renaming or replacing a file.

The doodle numbers are stable catalog identifiers, not creation years. Do not invent image titles, chronology, personal stories, or alternative text beyond what the artwork and confirmed context support.

## Commands And Checks

Inspect any future starter or generator output in a separate directory and merge deliberately without overwriting existing work.

- `pnpm run dev`: generate/watch UnoCSS and run Rspeedy, the VitePress guide, and the browser host.
- `pnpm run build`: generate styles, build Lynx, the host, and the guide, and verify essential static output.
- `pnpm run build:pages`: run the build and add route pages, `404.html`, and `CNAME` for GitHub Pages.
- `pnpm run generate:placeholders`: regenerate the blurred doodle placeholders after adding or replacing a doodle.
- `pnpm run check:guide`: check the guide's chapters, local links, and source references.
- `pnpm run preview`: serve `dist/` on port 4173 with runtime headers and deep-route handling.
- `pnpm run lint`: run ESLint.
- `pnpm run typecheck`: run strict Vue/TypeScript checking.
- `pnpm run test`: run Vitest tests for pure rules and content resources.
- `pnpm run format` / `pnpm run format:check`: write or check Prettier formatting.
- `pnpm run check`: run lint, typecheck, tests, and formatting checks.

Husky runs lint, typecheck, and format checks before each commit, validates Conventional Commit subjects, and runs tests before each push. CI runs `check` and `build`. Run checks appropriate to the change. Pure tests do not establish Web rendering or interaction behavior; verify affected layouts, navigation, language changes, carousel controls, keyboard behavior, and runtime loading in a browser. For documentation and asset-only changes, verify local links, catalog coverage, and file integrity as appropriate. Document only checks actually performed and distinguish configured commands from verified environments.

## Git

Use small Conventional Commits with an English body explaining concrete behavior. Follow the applicable co-author trailer rules. Do not bypass hooks. Ask separately before each push and before destructive Git operations. Role agents must leave Git mutations to the coordinator.
